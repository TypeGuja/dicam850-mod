# DiCam 850 firmware mod

[English](README.md) | **Русский**

Моды прошивки экшн-камеры **Digma DiCam 850** (SoC iCatch SPCA6500 / V35, сенсор Sony IMX386, фреймворк SP5K).

Здесь лежат **только инструменты и патчи**. Сама прошивка (`SPHOST.BRN`) принадлежит Digma/iCatch,
её в репозитории нет — патчеры применяются к твоей собственной стоковой прошивке.

> ⚠️ Прошивка модифицированного образа может окирпичить камеру. Сейчас проверенный способ прошить её
> обратно — только через меню камеры, а для этого стоковая прошивка должна загружаться (возможный
> аварийный путь через загрузчик найден, но ещё не проверен — см. ниже). Используй на свой риск.
> Проверено на HW4.0 (2023-08-23).

## Что умеет

- **Runtime-конфиг с SD-карты** (`runtime/`, текущая версия **rtcfg9**): камера при входе в видеорежим
  читает `G:\DICAM.CFG` и применяет для каждого режима свой битрейт (до 160 Мбит/с), кроп
  (2.35:1, 1.85:1 или высота) и потолок ISO по fps. Без файла — поведение стоковое.
- **Плавная автоэкспозиция**: правка `AECONFIG.BIN` (ConvergeSpeed/Limit) — без резких скачков яркости.
- **JSON-профили** (`profiles/`): битрейт и форматы «запекаются» в прошивку на этапе сборки.

## Конфиг `DICAM.CFG`

Одна строка на режим, учитываются только строки, начинающиеся с `mode=`:

```
mode=ШИРИНА,FPS,БИТРЕЙТ,КРОП[,MAXISO]
mode=3840,30,90,235          ← 4K30, 90 Мбит/с, кроп 2.35:1
mode=1920,60,40,0            ← 1080p60, 40 Мбит/с, без кропа
```

- `БИТРЕЙТ` — Мбит/с 10..160, `0` = не трогать. Выше ~80 нужна карта V30/U3.
- `КРОП` — соотношение ×100 (`235`, `185`) или высота кадра; `0` = не трогать. Только обрезка, без растяжения.
- `MAXISO` — необязательный потолок ISO для этого **fps** (общий для всех режимов с тем же fps).
- **Комментарий (`#`) пиши только отдельной строкой.** В rtcfg8 цифры из хвостового комментария
  (`mode=1920,60,40,0  # 1080p 60`) читались как MAXISO=1080 → в помещении темно. В rtcfg9 всё после `#`
  игнорируется, но лучше так не делать.

### Про ISO

- ISO — это **усиление сигнала**, а не чувствительность матрицы: каждое удвоение = +1 ступень яркости
  и столько же шума. Выдержка в видео не длиннее 1/fps, поэтому на 60/120/240 fps камера раньше
  уходит в усиление (120 fps ≈ на 2 ступени больше усиления, чем 30 fps при том же свете).
- В фото-меню есть пункт ISO (только для фото). В видео-меню ISO нет — только через `MAXISO`.
- В таблицах экспозиции (AEPCHART) ISO — это байт усиления. Принятая (на железе не проверенная) шкала:
  `96 = ISO100`, +16 на ступень (`144 = ISO800`, `160 = ISO1600`). Стоковые AUTO-таблицы содержат
  **одну** «тёмную» строку с высоким усилением (160 ≈ ISO1600; у 60 Гц/120 fps — 120), остальные — 80–112.
- **Ограничение текущей реализации:** rtcfg8/9 выкидывает строки выше потолка, поэтому любой `MAXISO`
  ниже ~1600 фактически даёт ISO100 (в помещении темно). Пока лучше не задавать. План — выставлять
  усиление тёмной строки ровно в потолок (тогда можно будет и **поднимать** ISO выше стока; AGC сенсора
  умеет до ×65, сейчас используется ×5.6).
- Практика: днём потолок не нужен; в помещении/ночью — без потолка и 30 fps вместо 60/120;
  потолок даёт более чистую, но более тёмную картинку, а не более светлую.

## Состав

| `brntool/` | Rust: разбор/распаковка/замена файлов/патч по VA/пересчёт контрольной суммы `SUNP BURN FILE` |
| `runtime/hook/` | Rust `no_std` (Thumb, Cortex-A7): код хука, линкуется прямо в свободное место образа @`0x4075fd94` |
| `runtime/build_rtcfg.py` | вшивает `hook.bin` + 2 перехвата + снимает потолок VBRC, проверяет каждый байт |

| `runtime/DICAM.CFG` | пример конфига для карты |
| `profiles/` | `diprofile.py` + примеры JSON |
| `firmware/` | скрипты анализа: контрольная сумма, FAT-том `RO_RES`, заголовки, xref/дизасм |
| `probe/` | PTP/IP-зонд камеры по Wi-Fi (только чтение) |

## Сборка

```sh
cd brntool && cargo build --release
rustup target add armv7a-none-eabihf
cd runtime/hook && cargo build --release
# objcopy -O binary target/armv7a-none-eabihf/release/dicam_hook ../hook.bin
python -I runtime/build_rtcfg.py <база.BRN> <выход.BRN>
python -I runtime/emu_test.py <папка с unicorn> <выход.BRN>
```

Прошивка: положить результат в корень SD как `SPHOST.BRN` → меню камеры → обновление ПО.
Контрольная сумма BRN: сумма всех LE u32-слов ≡ 0 mod 2³², компенсирующее слово @`0x1fc`.

## Устройство `SPHOST.BRN` (rev4, ≈15.5 МБ)

| Смещение | Размер | Что |
|---|---|---|
| `0x000000–0x0a7000` | ~668 КБ | Заголовок `SUNP BURN FILE` + **загрузчик второго уровня** (`$unp_0.7.14_sysboot`, «iCatch sd/spi loader II»), параметры DRAM (`DRAMPARA`), `PHYTABLE` |
| `0x0a7000–0x0a8120` | | `SUNP BURN HDR 1/2` (HDR2 — таблица образов дисков, XOR 0x7a) |
| `0x0a8120–0x4a8120` | 4 МБ | Диск `A:` — ресурсы `RO_RES` (меню, шрифты, звуки, IQ-таблицы, `DIQ.FIF`) |
| `0x4b8120–0xebf320` | ~10.5 МБ | Основная прошивка «DRAM CODE», грузится по VA `0x40000000` |
| последние `0x250` | | `SUNP BURN HDR 3` — список файлов покамерной калибровки (`BADPIX`, `DEFPIX`, …) |

### Загрузчик и восстановление без разборки (найдено, НЕ проверено)

Загрузчик живёт отдельно от основной прошивки и сам умеет прошивать. По строкам в нём:

- **Card ISP с карты в обход основной прошивки:** `Button pressed`, `skip load FW`, `card file %s`,
  `D:\firmware.brn`, `cardISP progress`, `FW boot error %x` — вероятно, при зажатой кнопке при включении
  и/или при ошибке загрузки он прошивает `firmware.brn` с карты.
- **Два слота прошивки:** `update/keep original Firmware1/Firmware2`, `Boot from priority %d`,
  `RawCBoot … chksum NG` — возможен откат на второй слот.
- **USB ISP:** вендорские запросы `0x76–0x79`, `0xFD` («iCatch ISP Version»).

Если подтвердится — это путь восстановления без программатора. Условие: область загрузчика во всех
наших сборках должна оставаться байт-в-байт стоковой. Следующий шаг — разобрать код условия
(кнопка/`D:\firmware.brn`) и проверить его на **стоковой** прошивке.

### Что внутри основной прошивки

ОС ThreadX + ~28 000 функций (~5.4 МБ кода) и ~5 МБ данных. Опознана примерно треть кода (нижние границы):

| Модуль | ≥ |
|---|---|
| Сенсор и обработка картинки (IMX386, CDSP, AE/AWB, WDR/HDR, LSC) | 512 КБ |
| Wi-Fi Realtek RTL8188 | 254 КБ |
| Видео: H.264, VBRC, запись MOV | 242 КБ |
| Дисплей, меню, OSD | 194 КБ |
| ФС, SD, флеш | 149 КБ |
| Сеть: TCP/IP, HTTP, RTSP, PTP/IP | 133 КБ |
| Приложение: режимы, кнопки, питание | 128 КБ |
| Ядро ОС, память, libc | 85 КБ |
| USB (MSC, UVC, PTP) | 69 КБ |
| Звук (AAC/WAV) | 36 КБ |
| Гироскоп, стабилизация | 25 КБ |

DDR/PLL настраивает загрузчик, поэтому своему образу их поднимать не нужно. Без открытой документации
остаются CDSP (обработка картинки), кодек H.264 и Wi-Fi — их разумно оставить стоковыми и вызывать
как библиотеки, а всё остальное (приложение, меню, AE, настройки, запись, USB, сеть) переносить на Rust.

## Резкость и шумоподавление (исследование, на паузе)

Анализ дневного клипа (1920×816@60, 40 Мбит/с): битрейт и экспозиция в порядке, картинку портят
**ореолы перешарпа** на контрастных краях и «акварель» шумодава на листве.

- Динамические IQ-блоки `.257` из `DIQ.FIF` применяются функцией `0x40629c34`: секции
  `{u32 size, u16 type, u16 count}`, записи `{u16 len=0xc, u8 kind, pad, u32 reg, u32 val}`.
- Все значения проходят через две точки: `BL 0x4060a32c` @`0x40629c94` и @`0x40629d84`
  (`r1` = регистр, `r2` = значение). Вызовы type 4 (`0x40629cd4`, `0x40629de8`) передают указатель — не трогать.
- Кандидаты (карта регистров CDSP закрыта NDA): `0x07170202/0211/0220` — похоже на резкость/края,
  `0x07170271`, `0x0717028d` — пороги шумодава, `0x071c014b`.
- План: перехват обеих точек + `iq=РЕГИСТР,ПРОЦЕНТ` в `DICAM.CFG`. **Блокер — место:** хук занимает
  609/612 Б, других свободных мест в коде нет (нули в заголовке образа @`0x40000070` трогать опасно).
  Место освободится заменой обрезки ISO на запись усиления в одну строку.

## Грабли, на которые уже наступили

- Нули сразу после функции могут быть хвостом её таблицы (`__clzsi2` @`0x4075fd84`) — rtcfg2 испортил картинку.
- «Пустые» 16 КБ @`0x409ffa83` — это таблица менеджера питания и буфер сохранения SRAM.
- `fsSimpleRead` возвращает 0 = OK, а не число байт.
- Чтение файла с SD внутри AE-колбэка голодит кадр на 60/120/240 fps; правка gain «на месте» ломает
  монотонность коротких AEPCHART — поэтому в rtcfg8 строки таблицы обрезаются, а не перезаписываются.
- Парсер rtcfg8 читал цифры из комментария после `#` как MAXISO — исправлено в rtcfg9 (тест `[5b]` в `emu_test.py`).
- Функция без ссылок по BL/литералам ещё не мёртвая: в «мёртвую» `0x405d78c4` есть переходы извне.
